# The capability curve

Short session (clip is the blurb): frontier models are getting more capable, fast — where
the curve is going and what it means for developers on Claude. This page also serves as the
vault's **hub for the capability-curve idea**, which recurs across the July 2026 Code with
Claude batch.

## The recurring narrative
- **Concrete rungs** ([[production-faster-managed-agents]]): Opus 3 → generate a test
  function (approve every tool); Opus 4 + [[claude-code]] → drive a whole feature / a PR
  (still steering); **[[opus-4-7]]** → clear entire backlogs, wake to merge-ready PRs.
  Next: a quarter of work in a few hours via agent swarms.
- **Two engines of the curve** ([[the-thinking-lever]]): train-time compute (bigger models)
  and [[test-time-compute|test-time compute]] (more tokens thinking); the **METR** benchmark
  tracks the growing hours of autonomous human work models can complete.
- **Implication for orgs** ([[ai-native-engineering-org]]): the bottleneck is now
  **infrastructure and process**, not intelligence.
